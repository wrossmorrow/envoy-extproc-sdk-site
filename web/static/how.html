    Worth noticing

    • Envoy holds the request the whole time. Nothing is forwarded while a phase is paused. The processor only ever sends back instructions: mutations, or an immediate response.
    • Phases only happen if there's something to process. A GET has no request body, so that phase is skipped. Trailer phases are switched off in this demo's Envoy config.
    • Rejecting is an immediate response. At a request phase the upstream never sees the request. At a response phase it already has; you only replace what the browser gets.
    • It fails closed. If nobody decides before the phase deadline, the controller answers with a rejection, so a stalled human can't leave a request hanging forever.
    • Each phase is one round trip on long-lived streams. One ext_proc stream per exchange between Envoy and the processor, mirrored by one Process stream to the controller, both closed when the exchange ends.
    • Each extproc is implemented using SDKs linked below. These are open source public SDKs intending to help make programming for this feature easy.
